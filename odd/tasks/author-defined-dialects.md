## Specs

- S1 Identity: "an author-defined dialect's identity is its package name. `defineDialect({ name })` is required for an author-defined dialect, and the conformance fixture checks that `name` equals the package.json name. `find` and the Dialect declaration use that same name (e.g. "@company/ini-dialect")." SDK dialects carry no name and are never declared. `withOps`/`withoutOps`/`overrideOps` keep the base dialect's name (assumption, sent to architecture).
- S2 Registration surface exported: "Export the Dialect contract (parse, ops, print, declared extensions), the registration surface (defineDialect / byExtension) and the conformance fixture." Entry point pending architecture decision (subpath `./dialect` recommended).
- S3 Declared-set gate: "`find` rejects a handle of an author-defined dialect unless it is declared in the Manifest of the schematic's resolution scope (CA-5)". Failure deferred to factory end: "the factory fails because the dialect "ini" is not declared in the Manifest", "the file "settings.ini" has its original content".
- S4 Fixture package contract: "The package exports `<pkg>/conformance` (default export DialectFixture). The bin is `pbuilder-conformance --dialect <installed package dir>`, run from the resolved SDK root under engines.node. A missing `conformance` export fails as `fixture_missing`, never as a skip."
- S4a (2026-11-27, Daniel via architecture, verbatim): "`pbuilder-conformance` must run under Bun and resolve the dialect and `@pbuilder/sdk` through the same per-Frame pointer dir on NODE_PATH. Drop the `engines.node` spawn for this bin; codegen (R-8) is unaffected." Supersedes S4's "under engines.node".
- S5 Fixture outcomes: "A non-zero exit from a completed fixture means "fails the conformance fixture" (exit 1, with the JSON line). A crash, timeout or unparseable stdout means "the fixture could not run"." "keep exit 1 reserved for a real fixture failure." Output: `{"passed":bool,"dialect":"<name>","version":"<v>","failures":[{"case":"<fixture case id>","reason":"<rule + check>"}]}`, never echoes the author's values (A-87). `fixture_missing` exits 1, reported as `failures:[{case:"fixture_missing",...}]`.
- S6 Runner flag: "`--dialects <json>` = `[{name, version, root}]`, one per Frame, a missing flag meaning an empty set." "Carry `version` and do not check it at runtime." The bridge shares the argv parser. No second dynamic import() (FF-39/ADR-0054).
- S7 Pre-run check: "before the factory starts, the runner resolves each declared dialect from the factory's directory and requires its real path inside the package the Lock pins. Otherwise "the factory does not start because the dialect "X" resolves outside the package the Lock pins", which names the dialect and changes no file." A-4 guarantee, not a security boundary.
- S8 Handles of two Dialects on one file keep both edits (A-7), incl. an author dialect sharing `.ts` with the SDK's.
- S9 Acceptance: the A-16 scenarios are the acceptance tests (needs a `v*` architecture tag for the submodule pin).
